# Instructions for agents

This repository automates part of an Arch Linux post-installation setup. Keep commands readable, reviewable, and safe to repeat.

## Interface and scope

- `archsetup` is the public CLI. The only shell entry point is `install.sh`, which installs prerequisites, builds the Rust binary, and runs `link`; do not reintroduce Bash modules or commands. `link` points `~/.local/bin/archsetup` to `target/release/archsetup`. `src/cli.rs` parses commands, `src/commands/` executes them, and `src/project.rs` locates the repository. Every public CLI command is implemented in Rust. Use `--dry-run` for previews without changes; do not reintroduce `plan/apply` or the old `install`, `uninstall`, or `packages` command names.
- CLI messages, installer messages, and profile descriptions must be in English. Update output tests when changing those strings.
- Rust uses a lean hexagonal architecture in one crate. The CLI and adapters depend on use cases, never the reverse. Define small ports for each use case that reads or changes external state; keep rules and decisions in `src/application/`. Do not create crates or traits without need. Summary `doctor` and `link` planning already follow this split; detailed diagnostics are still being migrated.
- `src/adapters/desktop/` applies Xfce, Ly, and X11 touchpad settings. `desktop` checks the existing state and skips matching settings without restarting the panel or requesting sudo; it supports an optional compatible hardware profile. `restore` preserves the installed command; `unlink` removes only the link and recorded PATH entry. Legacy Bash code has been removed; an old launcher link can be updated with `./target/release/archsetup link` after building.
- ArchSetup does not configure disks, partitions, boot, power management, or snapshot recovery. The Acer profile may select the legacy NVIDIA driver in the optional `gaming` category after checking conflicts and headers; never remove drivers automatically. Do not add formatting or unlocking to the CLI without a new explicit request.
- Do not create empty directories as placeholders for future features.

## Packages and profiles

- `packages/official/<category>.txt` and `packages/aur/<category>.txt` are shared lists. Categories are `base`, `development`, `apps`, `theme`, `desktop`, `gaming`, and `emulation`; the default is `base development apps theme desktop`. Each `profiles/<identifier>/profile.toml` contains metadata, extra packages, and supported settings. The profiles are `generic` and `acer-aspire-vx5-591g`.
- Without `--profile`, use only shared lists. `generic` is an explicit equivalent with no hardware-specific additions. `doctor` may suggest profiles based on DMI vendor and model, but must never select one automatically. Hardware profiles require `match_vendor` and `match_dmi` for the base model.
- Keep the TOML schema documented in the README. Reject unknown fields; do not execute arbitrary commands from a profile. Add headers to `gaming` when the profile selects `nvidia-580xx-dkms`, according to installed kernels; `base` must not install headers without DKMS. Do not reinstall disk utilities selected in archinstall as part of `base`.
- Classify packages by function. Put GPU, CPU, or other device dependencies in a profile. Prefer official packages and use exact Arch package names. Each list line contains one package and no shell arguments; blank lines and comments beginning with `#` are allowed.
- The repository has no saved archinstall configuration. Before adding a package, check whether archinstall already installs it on the target system directly, through a group, or as a dependency.
- Update the category table in `README.md` when changing a package list.
- `--dry-run` must not modify files, packages, or settings. Validate prerequisites before the first change. Run commands as a regular user and use `sudo` only when necessary.
- Repeated installation must skip packages already installed and avoid `pacman -Syu` when nothing is missing. Apply this to `install.sh` and `pkg`; `aur` already skips when its helper exists. Keep the full Arch system update paired with installing missing official packages.
- Without `--dry-run`, `aur` and `pkg` install with `--noconfirm` and no additional confirmation prompts. `aur` shows the PKGBUILD and lists the other files before running `makepkg`; never run `makepkg` as root. `pkg` prefers `paru` but accepts an existing `yay`. If no helper is available and AUR packages are selected, report the dependency and offer to run `archsetup aur` before installing. Do not read or store the user's password; use `sudo`'s own temporary authentication cache.
- `aur` installs `rustup` before building only if neither `rust` nor `rustup` is available. `pkg development` uses an installed `rust` and omits `rustup` in that case; never remove `rust` automatically. Initialize the stable toolchain only when `rustup` is selected as the provider. Check the selection in `--dry-run` as well.
- `pkg development` installs Docker Engine and Compose, adds the current user to the `docker` group only if needed, starts `docker.service`, and enables it at boot. Make these actions idempotent. Warn that new group membership requires another login.
- `aur` and `pkg` record the package inventory before installation and newly installed packages after each run, including partial failures. `restore --packages` removes only recorded new packages, after checking dependencies with `pacman -R --print`; do not use `-Rns` or infer packages from repository lists. `restore` without that option does not remove packages; `unlink` never removes packages.

## Hardware and data

- Collect diagnostics on the target machine before applying hardware settings. Profile descriptions are hypotheses until checked locally. Require an explicit profile and validate compatibility before changing drivers, boot, power, device-specific touchpad settings, or file systems.
- The shared natural-scrolling rule uses `MatchIsTouchpad` in Xorg and does not require a profile. Tap-to-click requires `touchpad_tapping = true` in the profile and DMI validation; keep both rules restricted to X11 touchpads.
- Back up existing files before editing them. Repeated commands must not duplicate entries or plugins.
- Do not commit passwords, tokens, serial numbers/SNIDs, or complete diagnostics to the repository. `acer-aspire-vx5-591g` represents the base model; do not assume all variants have the same components.
- Never infer a disk from `/dev/sdX` or capacity. Any documentation about disks or restoration must require verification on the machine and must not promise a complete rollback without testing.

## Xfce

- Themes, fonts, and layout are shared across machines. Xfce is the current default and the only desktop supported by `desktop` and `all`; both run as a regular user in an Xfce X11 session. Require `xfce4-session` and `xfce4-panel` and an active Xfce session before any changes; `all` requires this before running `aur` or `pkg`, and `doctor` reports it as a warning. If packages needed by `desktop` from the `desktop` or `theme` categories are missing, offer to run `archsetup pkg desktop theme` before editing files. Xfce is a prerequisite installed by archinstall or manually. Preserve Ly and other display managers; do not replace them automatically.
- Back up Xfconf and panel settings before changing them. Repeated runs must not duplicate panels or plugins.
- `restore` must use the first backup made before changes, preserve files with unproven ownership, and restore Xfce XML files only outside the graphical session.
- The dark Nordic top panel is 40 pixels high with 28-pixel icons. Fill the Arch menu button at the left edge with a subtle background; use one expanding separator after tasks and small invisible separators between the workspace pager, status icons, session menu, and clock. Preserve other user plugins. Use Docklike for grouped icon-only windows with hover previews even for a single open window when installed, and the native tasklist as a fallback. Keep compact native workspace previews; never change Xfce's workspace count or names. Do not add Verve. Show the native actions menu with a sharp white 32-pixel SVG user icon inspired by Zafiro Dark via a scoped GTK CSS rule, and use larger Inter fonts and spacing for menus, calendar, and clock. Preserve unrelated GTK CSS and back it up; back up the installed SVG too. Omit the keyboard LED indicator from the panel and package list. Reuse the existing clock and do not recreate the lower dock. During migration, remove only the Genmon instance identified as the project's old indicator and preserve the old script in the backup. The menu uses `/usr/share/pixmaps/archlinux-logo.svg`, provided by `filesystem`.
- Use Whisker Menu with the Arch logo so a second Super press closes it, including after opening it with the mouse. Reuse an existing Whisker instance or convert the existing Applications Menu instance in place; do not leave two menus on the panel.
- Reuse the native Xfce systray, or add one if absent. Hide known StatusNotifier and legacy icons behind its native expand arrow, and hide newly discovered icons by default because NetworkManager's icon label changes with signal strength. Keep the systray between the workspace pager and user actions. Remove only the obsolete ArchSetup-marked tray popup Genmon plugin and its generated script, preserving unrelated Genmon plugins. Back up settings and files before migration.
- Keep the Xfce PulseAudio panel plugin visible beside the native systray arrow, with keyboard shortcuts, MPRIS, and multimedia keys enabled. Xfce panel plugins cannot be nested inside the native systray. Disable Pasystray's global autostart through a backed-up user override and stop its running process so the old tray icon does not duplicate the plugin. Preserve the original override for restore. Remove only ArchSetup's older custom `pactl` and `playerctl` keyboard shortcuts when they match the commands ArchSetup previously installed, preserving unrelated user shortcuts.
- The active configuration uses Nordic for GTK/xfwm4, Zafiro Dark (`zafiro-dark`) for icons, Hackneyed for cursors, and Inter for the interface. Fira Code is the extra font for code. Also configure `~/.Xresources` and `~/.icons/default/index.theme`, preserving other settings and backing up files before editing them.
- When Ly is enabled, `desktop` sets `animation = doom` and `clock = %d/%m/%Y %H:%M` in `/etc/ly/config.ini`. Preserve other settings, back up the file before editing it, and do not restart the session while applying changes. Xfce's screensaver handles inactivity locks; Ly is a login manager for new sessions. Leave other display managers unchanged.
- `ksuperkey` belongs to the AUR `desktop` category; `desktop` binds `Alt+F1` to the applications menu and starts the daemon once through Xfce autostart. Preserve conflicting existing shortcuts and back up Xfconf and autostart before changing them.

## Verification

- After changing Rust, run `cargo fmt --check`, `cargo test`, and `cargo build --release`. Test the binary with a temporary repository and HOME; no test may install packages on the development machine.
- After changing `install.sh`, run `bash -n install.sh` and check its output in a non-Arch environment; do not run a real installation on the development machine.
- Rebuild the Rust binary after code changes; do not restore the launcher or Bash modules.
- After changing package lists, check `archsetup pkg --dry-run` with and without the Acer profile, and test changed categories separately. Invalid profiles and categories must be rejected.
- Check `archsetup aur --dry-run`, `archsetup desktop --dry-run`, and `archsetup link --dry-run`, including rejection of invalid arguments. Confirm previews do not change files. Test missing, accepted, and declined dependency flows with simulated commands; never install packages on the development machine.
- Check `archsetup unlink --dry-run` and `archsetup restore --packages --dry-run`; test link creation and removal with a temporary HOME. Never run a real restore on the development machine.
- Check `archsetup doctor`, `archsetup doctor --verbose`, and `archsetup doctor --profile acer-aspire-vx5-591g`. On an incompatible machine, the profile must fail without changes; run profiled `pkg` without `--dry-run` only on a verified compatible machine.
- Do not run `pkg`, `aur`, or `desktop` without `--dry-run` on the development machine. Test application on a target Arch system; for `desktop`, use a real Xfce X11 session with a configured display manager.
